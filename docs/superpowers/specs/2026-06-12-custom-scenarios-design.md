# 自定义场景（预设提示词） — 设计文档

日期：2026-06-12
状态：待评审

## 背景与目标

用户经常对选中内容做同类操作（翻译、总结、代码解读……），每次手敲指令重复且低效。
本功能允许用户**自定义场景**：一个场景 = 名称 + 一段指令文本（纯文本，无模板变量），
激活后作为上下文注入会话，让 Claude 按场景要求处理后续内容。

需求决议（已与用户确认）：

1. **生效粒度**：会话级，可中途切换——首次发送注入场景指令，后续追问靠会话记忆延续；
   中途切换场景则在下一条消息重新注入
2. **提示词形态**：纯指令文本（不支持占位符模板）
3. **管理 UI**：选择与增删改全部在侧边栏内完成
4. **预置场景**：首次播种 4 个（翻译 / 总结要点 / 代码解读 / 润色改写），可改可删，删后不复活

## 非目标

- 占位符模板（`{{选中内容}}` 等）——YAGNI，纯指令已覆盖绝大多数需求
- 场景跨设备同步（用 `storage.local`，不用 `storage.sync`）
- 撤销已注入的旧场景指令（切换是追加注入，旧指令仍在会话历史中；要完全干净开新对话）
- 场景的导入/导出

## 总体方案（已确认：方案 A）

panel 管理场景库与激活状态，发送时多传一个 `scenario` 字段；
background 透传；host 把场景指令拼在 **prompt 最前面**。

## 数据模型

`chrome.storage.local`（持久，与选段所用的 `storage.session` 生命周期不同）：

```js
scenarios: [            // 场景库
  { id: "uuid", name: "翻译", prompt: "你是专业译者。..." }
]
scenariosSeeded: true   // 预置场景只播种一次；用户删除后不复活
```

panel 内存状态（面板关闭即丢，与「关闭侧边栏=会话结束」的现有语义对齐）：

```js
activeScenarioId   // 当前激活场景 id；null = 无场景
injectedScenario   // 本会话已注入的 { id, prompt } 快照；null = 尚未注入
```

## 注入规则（核心逻辑）

发送时（`doSend`）：

1. 取激活场景 `active`（从 `scenarios` 按 `activeScenarioId` 查找）
2. **需要注入** ⇔ `active` 存在 且（`injectedScenario` 为空 或 `active.id !== injectedScenario.id`
   或 `active.prompt !== injectedScenario.prompt`）——按 id **加 prompt 文本**比较，
   这样编辑激活中场景后，下一条消息自动按新文本重新注入
3. 需要注入 → 消息携带 `scenario: active.prompt`，发送后 `injectedScenario = { id, prompt }` 快照
4. 不需要注入 → `scenario` 传空，省 token
5. 「新对话」→ `injectedScenario = null`（激活状态**保留**，开新对话继续用同场景不必重选）
6. 取消激活（再点一次胶囊）→ `activeScenarioId = null`，后续消息不再注入
7. 发送条件不变：仍需 question 或选段至少其一，仅激活场景不构成发送条件

注入消息的 user 气泡显示 `🎭 场景名` 前缀，让会话里看得出哪条消息带了场景。

## 组件职责

### host.js（≈6 行）

`handleMessage` 透传 `msg.scenario`；`runClaude(context, question, scenario, resumeId)` 分段拼 prompt：

```
【场景要求】          ← 有 scenario 时置于最前
<scenario>

以下是页面选中的内容：  ← 有 context 时
---
<context>
---

<question>            ← 兜底：有 scenario 时为「请按上述场景要求处理」；
                         无 scenario 时维持原文案「请根据以上内容给我一个总结或分析」；
                         无 context 无 scenario 时维持原兜底「你好」
```

`scenario` 为空/未定义时行为与现状**逐字节一致**（向后兼容：host 未更新时场景指令被忽略，其余功能正常）。

### background.js（1 行）

panel 长连接转发处给 `native.postMessage` 增加 `scenario: msg.scenario`。

### panel.js（≈120 行）

- 启动：读 `scenarios` + `scenariosSeeded`；未播种则写入 4 个预置并置 `scenariosSeeded: true`
- 监听 `storage.onChanged`（`local` 区域）重渲染胶囊条与管理视图
- 胶囊条交互：点选激活 / 再点取消；激活态高亮
- 管理视图增删改直接写 `storage.local`；删除激活中场景时同步 `activeScenarioId = null`
- `doSend` 按上述注入规则携带 `scenario` 字段

### panel.html

- 输入区上方新增场景胶囊条（横向滚动）+ ⚙ 管理按钮
- 管理视图：默认隐藏的面板（位于消息区上方），含场景列表（名称 + ✎ + ×）、
  「＋ 新建」按钮、编辑表单（名称单行输入 + 提示词 textarea + 保存/取消）

### content.js

零改动。

## UI 设计

```
┌──────────────────────────────────────┐
│ header / toolbar（不变）              │
├──────────────────────────────────────┤
│ ▼ 管理视图（默认隐藏，⚙ 切换）        │
│   翻译            ✎  ×              │
│   总结要点        ✎  ×              │
│   ＋ 新建场景                        │
│   [编辑表单：名称 / 提示词 / 保存 取消] │
├──────────────────────────────────────┤
│ 选段 context-bar（不变）              │
│ messages（不变）                     │
├──────────────────────────────────────┤
│ [🎭翻译][总结要点][代码解读][润色][⚙]  │ ← 胶囊条，激活项高亮
│ 输入框                          [↑]  │
└──────────────────────────────────────┘
```

- 胶囊显示场景名（超长截断）；激活态用深色底高亮；0 个场景时只显示 ⚙
- 视觉风格延续现有 toolbar 按钮样式（浅底、细边框、12px）

## 预置场景

| 名称 | 提示词 |
|------|--------|
| 翻译 | 你是专业译者。把内容准确翻译成中文；专业术语保留原文并加简短注释；最后用一两句话说明整体语境或关键难点。 |
| 总结要点 | 用条目式列出内容的核心要点，按重要性排序，每条一句话；最后给出一句话的整体结论。 |
| 代码解读 | 你是资深工程师。解释这段代码的功能、关键逻辑与执行流程，指出潜在问题或坑，必要时给出改进建议。 |
| 润色改写 | 在保持原意的前提下润色这段文字，使其更通顺、专业；输出润色后的全文，并简要列出主要修改点。 |

## 边界与错误处理

| 场景 | 行为 |
|------|------|
| 删除激活中的场景 | 自动取消激活（`activeScenarioId = null`）；`injectedScenario` 保留（已是会话历史事实） |
| 编辑激活中场景的提示词 | 下一条消息按新文本重新注入（注入比较含 prompt 文本） |
| 场景激活 + 仅选段无问题 | host 兜底问题变为「请按上述场景要求处理」，避免与场景指令打架 |
| 仅激活场景、无选段无问题 | 不满足发送条件，不发送（与现状一致） |
| 关闭重开面板 | 场景库保留；激活状态重置为无（与会话生命周期一致） |
| host.js 未更新（旧版） | `scenario` 字段被忽略，场景不生效，其余功能正常 |
| storage.local 读写失败 | 沿用项目现状：静默失败，以下一次 onChanged 为准 |
| 名称/提示词为空提交 | 保存按钮校验：两者必填，否则不保存并提示 |

## 测试策略（手动验收清单）

1. 更新扩展后首次打开面板：胶囊条出现 4 个预置场景 + ⚙
2. 点「翻译」激活（高亮），选中文字发送：回复按翻译要求执行；该条 user 气泡带 `🎭 翻译`
3. 同会话追问：气泡无 🎭 前缀（未重复注入），回复仍延续翻译场景行为
4. 中途切到「总结要点」：下一条消息气泡带 `🎭 总结要点`，回复按新场景执行
5. 再点激活胶囊取消：后续消息无场景注入
6. 场景激活 + 仅选段、不输问题直接发送：回复按场景执行（而非泛泛总结）
7. 新建场景：填名称+提示词保存 → 胶囊条出现新场景，可激活使用
8. 编辑激活中场景的提示词 → 下一条消息重新注入（气泡再次出现 🎭 前缀）
9. 删除场景：胶囊消失；删除激活中场景时高亮消失、后续不注入
10. 删光全部场景 → 重载扩展：不复活，胶囊条只剩 ⚙
11. 关闭重开面板：场景库还在，无激活场景
12. 名称或提示词留空保存：被拦截并提示
